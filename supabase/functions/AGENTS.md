# Edge functions rules
- Self-service confirmations use the persistent payconf queue key rather than a pre-send claim; the existing payment polling worker recovers missing enqueues in bounded active-event batches, while cashback validates exact captured transactions and skips rejected earlier cascade payments.
- Correios settings are service-only; correios-admin validates JWT/admin, never returns access code or token, and invalidates cached tokens on credential/environment changes. sale-freight-quote validates PDV/expedition permission and sale access, batches indexed identifiers, quotes each source independently, and persists/chooses options for the entire server-resolved Conference shipment. Selection is service-only and atomic, rejects changed address/group/items, and never touches customer charges.
- MP refunds: JWT + estornos permission; admin-only refund_settings; gateway_refunds service-only writes, payment-id lock and idempotency; uncertain outcomes stay verificar. Poll-pending syncs; refund-post-actions handles history. Shared mp-sale-payment resolves sale or linked-order credentials in one batch; ambiguity fails closed. Converted order references are the same purchase. Gateway adapters live in _shared/refund-gateways/ (MP, Appmax); Appmax only when no approved MP payment and the new-account API shows it paid, integral-only (API gives no reliable refunded amount); legacy-account orders blocked; Point/Rinne/Pagar.me later.
- Refund badges: only RPC refund_badges_for_sources (batched, order↔sale aware); authenticated estornos users read all list scopes and pending counts, while approve/reject remain admin-only. Shared refund-list filters use stable created_at/id ordering; list enrichment batches source payment dates and account names to avoid per-row queries.
- Imported external refund receipts distinguish the purchase customer's corrected identity from the bank recipient evidence, preserve unverified timezone/reference provenance, and use the verified paid amount rather than the product total; never imply that a corrected customer name changes the refund destination.
