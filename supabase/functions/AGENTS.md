# Edge functions rules
- Paid cards use every grouped order plus WhatsApp broadcasts and the event read marker; chat opening stays separate from viewing/unifying, with no per-card queries.
- Manual Crossell reuses presets and bulk rows with an isolated atomic dispatcher; generic workers cannot claim them. Persist each confirmed file and next-block schedule; never reclaim uncertain sends. Validate exact selected instance, suppression and Meta incoming window before each message.
- Gateway email validation rejects invalid dot placement and domain labels before provider calls; use the existing technical fallback without guessing a real mailbox or rewriting customer data, so all callers share the same safe behavior.
- Self-service confirmations use the persistent payconf queue key rather than a pre-send claim; the existing payment polling worker recovers missing enqueues in bounded active-event batches. Unverified cashback does not block a paid notification or invent credit. AustPay GET may omit reference: require exact order-linked transaction, APPROVED, captured amount/time and no invalidation; reject explicit conflicting references and skip rejected earlier cascade payments.
- Correios settings are service-only; correios-admin validates JWT/admin, never returns access code or token, and invalidates cached tokens on credential/environment changes. sale-freight-quote validates PDV/expedition permission and sale access, batches indexed identifiers, quotes each source independently, and persists/chooses options for the entire server-resolved Conference shipment. Selection is service-only and atomic, rejects changed address/group/items, and never touches customer charges.
- Refunds: JWT + estornos permission, admin approvals, service-only writes and payment lock; adapters in _shared/refund-gateways/. Converted orders are one purchase; ambiguity fails closed. AustPay uses merchant direct route, full amount omitted, exact capture/history and shared settlement window before execute/approve; unknown dates fail closed and D+1 fallback is explicitly estimated. Worker reads uncertain refunds without retry. Manual completion requires server password reauthentication, exact gateway, protocol and nonfuture date; service-only atomic RPC serializes by payment and reuses pending row. Receipts distinguish manual declarations from provider confirmations. Partial API and loose endpoint stay blocked.
- Refund badges: only RPC refund_badges_for_sources (batched, order↔sale aware); authenticated estornos users read all list scopes and pending counts, while approve/reject remain admin-only. Shared refund-list filters use stable created_at/id ordering; list enrichment batches source payment dates and account names to avoid per-row queries.
- correios-shipment (pré-postagem v3) is service-only on correios_shipments/correios-labels: requires the latest quote's selected Correios option and an authorized NF-e 55 for every sale of the server-resolved group; one active shipment per sale (partial unique index) so retries return the existing one. Labels use the async CWS receipt/download flow (no synchronous label endpoint exists in v3) and combined PDFs embed the official label unchanged; dry_run validates without calling Correios.
- Meta Purchase: orders trigger only fires; meta-capi-event sets meta_capi_purchase_sent_at after Meta OK and logs every failure. Self-service fills fbc/fbp/IP/UA from the order's live_selfservice_accesses.advertising_signals (or unique same-event phone match); unverified cashback never blocks it (Appmax has no approval time).
- Self-service cashback verifies on the gateway that really approved (latest successful checkout attempt, then 'Pago via' note, then linked ids); if verification fails on a webhook/manual-paid order it still grants from paid_at and paid value (minus VPS) with a receipt note — a paid order must always earn cashback.

- Correios printing derives persisted thermal/A4 PDFs from the original official label and shipment-linked invoice keys; the default ERP 10x15 label copies the official DataMatrix payload verbatim (it carries a Correios token) and checks object/CEPs before drawing, while the official label stays available as fallback. Reopening and batch printing repair missing formats without creating pre-postage; PDF generation stays server-side.
- Checkout success cache prevents duplicate charges, never restores paid state. AustPay approvals: production re-query, captured, exact transaction/reference/amount, no invalidated attempt. Reversal: privileged DB, invalidated sandbox attempt, no remaining success. Audits: admin/read-only, 50 rows, ≤3 provider reads.
- Live catalog invites: one row per event+phone; the paid-order trigger only schedules (never blocks payment), live-catalog-invite enqueues via the self-service queue, and manual resends reuse the row with a new message key so auto invites stay single.
- AppMax: AppStore OAuth2 via appmax-install; appmax_installations credentials service-role-only, no fixed secrets.
- Meta Custom Audiences rules live in supabase/functions/meta-audience-sync/AGENTS.md.
- Payment webhook verification and carrier delivery detection rules live in supabase/functions/_shared/AGENTS.md.
- Password reset only via auth-password-reset (generic reply, 3/h per IP, 2/h per e-mail, security_events log); login_ok/login_failed are browser-declared events in security-auth-event.
- Public live catalog: only via live-catalog-public (server prices, cashback needs CPF match, reuses open cart, pays on self-service cart page); both catalogs use _shared/catalog-availability.ts for staff-enabled variants, never physical stock, keeping display and cart validation identical.
- Central de Trocas: reuse exchange_requests; support_links store token hashes only; eligibility never denies alone.
- IG comment moderation: webhook only enqueues non-live comments not copied to live_comments and wakes ig-comment-moderate (no cron); the worker classifies once, never hides on AI/API failure, reserves the private reply before sending, and pauses the queue on Meta rate limits or AI 402/403.
- Return NF-e (finalidade 4): nfe-devolucao-emitir runs _shared/devolucao-guard.ts before every emission (troca, reversa, reprocess) — reuse an equal-value note, block divergent ones and any sum above the original note; correios-reverse links its note to the single open troca of the sale.
- Return NF-e recipient/items come from the AUTHORIZED original XML (55) via _shared/devolucao-dest.ts, with registration/order only filling gaps (NFC-e 65 has no address); the event's saved key is used only if authorized; a precheck (UF, cMun matches UF, bairro, CEP, entry CFOP 1202/2202, PIS/COFINS CST 50–99) blocks sending to SEFAZ and records the missing data for staff.
- Central links stay reopenable until expiry: the page shows per-item progress and reverse posting code, and new requests are allowed only for items without an open request (checked again in central_submit_atomic).
- correios-reverse (reverse logistics, customer→Pérola, paid by our contract) uses its own correios_reverse_shipments table with an idempotency key, never correios_shipments; only contract reverse services 03301/03247 with logisticaReversa=S and a validity date; every new reverse is linked to the original sale/items, requires customer CPF (she is the sender) and first emits a return NF-e (nfe-devolucao-emitir reverse mode, reused on retry) whose number/key go in the pre-postage and whose emitter CNPJ is the recipient CNPJ, because Correios refuse reverse postings without a matching note. The PDV chat sends the code/PDF only on staff click.
- RH: admin-only rh_* + area password; /vaga uses service-only rh-public. rh-score atomically claims attempts, streams one answers-only Gemini call, persists partial on failure, never auto-retries; manual attempts capped server-side. After an automatic evaluation is saved, one WhatsApp notice is claimed only when enabled, using the configured uazapi instance with no automatic retry; tests/resends are admin-only. VAGA-RH alone uses the tolerant rh_vaga matcher and per-comment/message delayed queue with a dynamic idempotent link; inbound story replies/mentions and direct DMs share reservations, while ordinary DMs never run legacy story rules. Legacy keyword matching and live moderation stay unchanged. UI uses bounded RPCs, no polling.
- Delivery estimate, native Correios tracking and Meta Ads token rules live in their own function folders' AGENTS.md; imported refund receipt rules live in supabase/functions/_shared/AGENTS.md.
- Staff RLS/storage policies: is_team_member(auth.uid()), never bare authenticated (Google sign-in has no perms).
- Support AI stays shadow-only: DB queue groups by customer with 2-minute silence; indexed recent-sale/keyword and human guards run before AI. A 2-minute worker has a DB lease and two-item cap; every gateway HTTP request (including tool continuations/training) reserves the full model output window plus input bytes atomically and settles usage in daily summaries; unknown usage retains its reservation as charged estimate. Persistent denial/policy pauses prevent background probes. No sending/routing; CPF and identity guards remain server-only, and replay rounds stay separate. Shared policy guards resolved acknowledgements, shipping deadlines, silent handoff, public comments and one-time consolidation; links exist only on staff action.
