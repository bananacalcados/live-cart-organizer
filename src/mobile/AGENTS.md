- Mobile screens live only in src/mobile/ and never import desktop pages/screens (nor are imported by them); share only libs, hooks and small widgets, so desktop changes cannot break mobile. Business rules go to shared libs, never into a screen.
- /inventory mobile behavior follows app_settings.inventory_mobile_redirect (invite default = banner only, auto = redirect, off = nothing); desktop never queries it, so desktop rendering stays unchanged.
- Mobile scan balance sums per-device totals server-side (mobile_cycle_submit) and applies only changed sums through apply_stock_label_batch anchored at the last confirmed send, so resends never duplicate and sales after a count stay deducted.
- Mobile product list filters run server-side through mobile_masters_list (paged, same stock rule as legacy_masters_summary); never download all products to filter on the phone.
- Mobile product/variant creation goes only through mobile_create_product / mobile_add_variants (one transaction, request_id replay, server name-duplicate block); their PDV-row step (_mobile_pos_sync) is a SQL copy of create-master-product-pos and must stay identical to it—re-run the rollback comparison when either changes.
- Mobile PDV lives in src/mobile/pdv (/m/pdv/*), same ProtectedRoute modules and isExpeditionOnly rule as /pos; /pos invite follows app_settings.pos_mobile_redirect (off default, invite, auto), queried only on touch <768px. Decisions/inventory: docs/mobile-pdv/.
- Expedition models/read enrichment, scan matching and post-conference effects live in shared lib/pos modules; both UIs use pos_expedition_transition, whose sale locks precede item/check writes, so stale operators cannot duplicate completion. Mobile scan outbox persists before feedback and replays existing scan-log UUIDs through pos_expedition_scan_batch; pending scans block completion.
- Mobile WhatsApp reads server-paged conversation summaries and cursor-paged live/archive messages; one existing WhatsApp broadcast listener coalesces events before scoped reads, so desktop queries and timers remain unchanged.
- Mobile WhatsApp Option A keeps send endpoints untouched: synchronous per-conversation locks and persisted uncertain attempts never auto-retry; only explicit human retry dispatches, and provider echo matching fails closed on target/content/sender/time ambiguity.
- Mobile Expedition lists via mobile_pdv_expedition_ids_v2 (all stores default, SEDEX/moto first) and readiness/bulk rules in lib/pos/expeditionReadiness.ts; bulk advance runs one pos_expedition_transition per order so failures are reported per order. Edits reuse the desktop ExpOrderEditDialog (single save path).
- Mobile WhatsApp look lives only in whatsapp.css (scoped classes); visual changes never touch the send path.
- Mobile expeditionData reads the desktop address aliases without writing them; readiness adds shipping guards only at conference, so imported street fields and earlier stages never produce false blocks.
- Mobile expedition documents reuse existing fiscal/label endpoints with explicit fiscal confirmation; labels are existing-prepostage-only until shared creation handles uncertain provider outcomes safely.
- Mobile Instagram reads project Direct-only summaries and cursor pages server-side; comment filtering never changes desktop summaries, message storage, broadcasts or send endpoints.
