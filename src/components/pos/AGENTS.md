- Chat "Reversa" opens NewExchangePicker by phone; the reverse dialog inside it is locked to the chosen sale/items and correios-reverse link_troca ties its return NF-e to the new exchange, so no reverse exists without an exchange.
- Exchange replacement products are added only via RPC exchange_add_replacement (conditional total-0 sale linked by pedido_novo_id, prices from catalog, stock reserved by existing triggers) removed only via exchange_cancel and swapped only via exchange_swap_replacement (cancels old sale + unpaid difference link, logs historico_reposicao, then reuses exchange_add_replacement), so no revenue/CAPI/automation fires and stock returns.
- Exchange difference links only via RPC exchange_create_difference_link (server recomputes reposição−devolvido, frete grátis/cotado/fixo, custom-amount checkout sale with expedition_stage nao_aplica, seller = exchange seller); exchange_cancel cancels unpaid links and the guard blocks concluding the replacement while the link is unpaid.
- Exchange "Novo envio" (finalize with pedido_novo_id) never creates a mirror sale: it sets the exchange to aguardando_envio, which lifts the guard's conclude lock; the guard marks it concluida when the replacement's expedition concludes.
- Live cashback on PDV sales only via RPC set_sale_cashback (pos_sales.cashback_id/amount, server checks owner/minimum/single reservation and recomputes total); trg_pos_sales_recalc_after marks it used on payment, so the WhatsApp checkout never trusts browser discounts for cashback/voucher.
- Exchange→return conversion only via RPC exchange_convert_to_return from ConvertExchangeToReturnDialog (shared by every ExchangeInProgressCard), so the same TD record, return NF-e and reverse code are kept.
